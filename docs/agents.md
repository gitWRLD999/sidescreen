# Agent operating contract

1. Inspect `agent.ps1 -Action Status`. Use `agentScreen.id` and the returned bounds. If `available` is false, report that condition. The Windows display name can change after a topology change, so do not cache it forever.
2. `Windows` lists only windows on the agent screen. Use `Candidates` only to locate a specific window the user asked you to move. Re-enumerate before each move: handles can be reused after windows close.
3. Call `Move` with the fresh handle and `-ExpectedDisplayId` from Status. Read `FocusPreserved` and `CursorPreserved`. Stop and report interference if either is false; do not compensate with foreground activation.
4. Capture the agent monitor to a new file with that same expected display ID when visual verification is useful. Read the image through your normal image tool. Keep it local unless the user authorized sharing it.
5. For input, call `Inspect` with `WindowHandle` and `ExpectedDisplayId`. Choose a returned element and an advertised `Actions` entry. Call `Act` with the inspection's `ObservationId`, the element's `ElementId`, the same handle/display and `Operation`; supply `Value` for `SetValue`. Each inspection expires after two minutes and allows one attempt. Re-inspect after every action or refusal. Empty actions mean unsupported; no foreground-input fallback.
6. For optional CUA, read [cua.md](cua.md). `CuaObserve` returns tokens and a window PNG; `CuaAct` consumes that observation for one background action. Select tokens from that exact result and verify app state afterward. Read `driver.effect`, `focus` and `stop`. Unsupported background routes do not permit foreground escalation. Other CUA clients may invalidate snapshots.
7. Recover windows on request. Do not turn off the only active display. Leave driver enable/disable and elevation prompts to the user unless they explicitly requested those changes.

The CLI must run in the signed-in interactive Windows desktop. A service-session SSH shell may not see it; remote agents need an existing authenticated broker executing in that desktop session. SideScreen does not provision SSH, expose HTTP, distribute keys, or configure agent accounts. The optional Muse engine exports four MCP-shaped tools through the existing authenticated broker; see [cua.md](cua.md). A remote agent must still register and test its own MCP connection.

For background input, check `ok`, `stop`, `dispatched`, `verification` and `focus`. A timeout or error can happen after an action completed: stop and observe, never automatically repeat it or restore focus. Button notification delivery is not proof of task success. `CursorPreserved` is informational because human pointer movement is allowed. Read [background-input.md](background-input.md) for exact supported controls and focus-monitoring limits.

For ChatGPT computer use, identify the display, then match one returned app/window to the scoped `Windows` list by title and app. Treat computer-use IDs as opaque. Use its read-only window snapshot for observation and SideScreen `Inspect`/`Act` for supported background input. Built-in Windows clicks and typing automatically activate their target. For unsupported controls, use a separately verified app-specific input route or explain the limitation. Display scoping is not a sandbox for other tools.
